# Trademark policy

The ChitraGit **code** is MIT licensed: you may copy, change and redistribute it under the
terms in [LICENSE](LICENSE). The MIT licence does **not** grant rights to the project's
names or logos. This page says how you may use them.

## The marks

- the names **ChitraGit**, **chitragit**, **chit** (as the command name) and **KodeKavach**
- the ChitraGit logo and banner artwork in [`docs/assets`](docs/assets)
- the name **TTox.Tech**

## Always fine

- Saying that your project uses, works with, or is based on ChitraGit.
- Writing about ChitraGit, reviewing it, teaching it or linking to it.
- Packaging an **unmodified** official release for an operating system or package manager,
  keeping the name, as long as you do not suggest TTox.Tech made or supports the package.
- Keeping the name in a fork while you prepare a pull request to this repository.

## Needs a new name

If you publish a modified version (a fork that ships its own builds, a rebrand, a hosted
service), give it a name and logo that cannot be mistaken for ChitraGit, and say plainly
that it is not the official project. "Based on ChitraGit" in the description is welcome.

## Never fine

- Distributing builds under the ChitraGit name that were not built from this repository's
  release workflow, or that do not pass the checks in [SECURITY.md](SECURITY.md#official-builds).
- Using the marks in a domain, account name, package name or app-store listing in a way that
  suggests it is official.
- Using the marks for anything that collects credentials or tokens from users.

## Reporting misuse

Email **contact@ttox.tech** with a link. For copies that also remove the MIT copyright notice,
we may file a takedown under [GitHub's DMCA policy](https://docs.github.com/en/site-policy/content-removal-policies/dmca-takedown-policy).

If you are unsure whether your use is fine, ask the same address. We say yes to most requests.
